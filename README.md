# 本地新闻问答 RAG 系统

面向新闻资料查询场景的 RAG（检索增强生成）问答应用。将预先采集的中国新闻网新闻数据构建为本地向量知识库，用户通过自然语言提问，系统检索相关新闻片段并调用大模型生成回答，同时提供召回新闻的标题、发布时间和原文链接，便于核对信息来源。

项目实现了从数据预处理、向量入库、语义检索到网页问答的完整流程。Embedding 与向量检索在本地运行，答案生成通过远程 OpenAI 兼容接口完成。

## 技术栈

Python · ChromaDB · sentence-transformers · OpenAI Python SDK · Gradio · python-dotenv

## 核心实现

- **新闻预处理**：支持新闻列表及 `{"data": [...]}` 两种 JSON 结构，拼接标题、分类、时间和正文前 500 个字符作为检索文本，并保存来源元数据。
- **向量索引持久化**：使用 `all-MiniLM-L6-v2` 生成归一化向量，通过 ChromaDB 持久化存储；启动时复用已有索引，集合为空时补充入库。
- **检索增强生成**：将用户问题向量化，默认召回 Top-5 新闻片段，组装为模型上下文；通过提示词要求模型依据资料回答，信息不足时明确说明。
- **来源展示与交互**：使用 Gradio 提供网页聊天界面，支持查看本次召回新闻的标题、时间和原文链接。
- **配置与异常处理**：从环境变量或 `.env` 读取模型接口配置，对数据文件缺失、JSON 解析失败、检索及模型调用异常提供提示；未召回结果时跳过模型调用。

## 处理流程

```text
新闻 JSON -> 文本预处理 -> 本地 Embedding -> ChromaDB 持久化
用户提问 -> 问题 Embedding -> Top-5 检索 -> 上下文组装 -> 大模型回答
                                           |
                                           +-> 召回新闻来源展示
```

主要逻辑位于 `news_rag.py`，按预处理、入库、检索、生成和界面划分函数，便于逐步调试与替换模型。

## 本地运行

需要 Python 3.10+、可用的 OpenAI 兼容模型接口，以及自行准备的新闻数据。

**1. 安装依赖**

```bash
pip install chromadb sentence-transformers openai gradio python-dotenv
```

**2. 准备数据与配置**

在项目目录中放置 `news.json`，格式如下：

```json
[
  {
    "title": "示例新闻标题",
    "category": "科技",
    "time": "2026-09-25",
    "url": "https://example.com/news/1",
    "content": "新闻正文内容"
  }
]
```

在同一目录创建 `.env`，按所用服务填写配置，真实密钥请勿提交到仓库：

```env
OPENAI_API_KEY=your_api_key
OPENAI_BASE_URL=https://your-provider.example/v1
OPENAI_MODEL_NAME=your_model_name
```

**3. 启动应用**

在项目目录执行：

```bash
python news_rag.py
```

首次运行需联网下载 Embedding 模型。启动后访问 `http://127.0.0.1:7860`，根据已导入的新闻提问，例如“新闻库中有哪些科技相关报道？”，再点击“显示引用来源”核对召回内容。

## 当前边界与改进方向

- 当前使用预先采集的数据，未实现实时采集或索引增量更新；修改数据或更换 Embedding 模型后需重建索引。
- 当前按单条新闻截取正文，默认模型以英文语料为主；后续可对比中文 Embedding 模型，并引入分段与重叠窗口以改善长文本检索。
- 当前采用向量 Top-K 检索，未加入相关性阈值或重排序；提示词约束不能保证完全消除幻觉，来源列表展示的是召回材料，尚未实现答案逐句引用校验。
- 聊天记录用于界面展示，当前检索与生成只使用本轮问题；后续可加入多轮问题改写，并建立测试集评估召回率、答案忠实度和响应时间。
